# Трекер челленджа «Идеальная осанка» — Leptos CSR + неоморфизм

## Context

Есть идея: отслеживать личный челлендж по осанке. Нет ни дизайна, ни архитектуры.
Дополнительное требование, которое определяет всё остальное: проект должен быть учебным
пет-проектом на **Rust** — в него нужно заходить, читать код, изучать фреймворк и дописывать
своё. Дизайн — неоморфизм.

Отсюда: приложение не «самое простое из возможных», а «самое простое из возможных **на Rust
в браузере**». WASM ради одной галочки в день — это оверхед, и он здесь и есть цель.

Итог: статичная PWA, скомпилированная в WASM, без бэкенда, данные в `localStorage`,
хостинг на GitHub Pages.

## Принятые решения

| Что | Решение |
|---|---|
| Модель дня | одна галочка: выполнено / нет |
| Срок | фиксированные N дней (настраивается: 30 / 60 / 100 / любое) |
| Пропуск | мягко: текущая серия в ноль, челлендж продолжается, финиш по дате |
| Правка прошлого | тап по любому дню переключает его |
| После финиша | экран итога + «Начать заново» (сдвигает дату старта, историю НЕ трёт) |
| Экраны | один экран + модалки (настройки, календарь). Роутера нет |
| История | сетка челленджа N клеток на главном + календарь по месяцам в модалке |
| Платформа | PWA mobile-first, работает оффлайн |
| Напоминания | нет. Штатный будильник телефона |
| Хранилище | `localStorage` + экспорт/импорт JSON |
| Стек | Leptos 0.8 CSR + Trunk |
| CSS | один `style.css`, палитра в CSS-переменных |
| Тема | одна светлая + контрастный акцент (канон нарушаем там, где он мешает читать) |
| Деплой | GitHub Pages |
| Порядок | сначала статичный HTML/CSS-макет, потом оживление в Leptos |

**Допущение, принятое без вопроса:** день сменяется в полночь по локальному времени
устройства. Отметил в 00:10 после ночной тренировки — попало в новый день; лечится тапом
по вчерашней клетке, поэтому отдельной настройки «граница дня» не делаем.

## Модель данных

```rust
// state.rs
#[derive(Serialize, Deserialize, Clone, PartialEq)]
pub struct Challenge {
    pub name: String,            // "Идеальная осанка"
    pub start: NaiveDate,        // дата старта
    pub length: u32,             // N дней
    pub done: BTreeSet<NaiveDate>, // ТОЛЬКО выполненные дни
}
```

`BTreeSet` вместо `HashMap<NaiveDate, bool>`: отсутствие даты = не выполнено. «Пропуск» не
требует ни отдельного значения, ни миграции — он получается бесплатно. Serde пишет
`NaiveDate` как `"2026-08-10"`, так что JSON остаётся читаемым руками.

**Ничего производного не храним.** Серия, счётчик, процент, признак финиша — функции от
`Challenge` + `today`:

```rust
pub fn day_number(&self, today: NaiveDate) -> i64      // (today - start) + 1
pub fn done_count(&self) -> usize                       // только дни внутри [start, start+N)
pub fn is_finished(&self, today: NaiveDate) -> bool     // day_number > length
pub fn current_streak(&self, today: NaiveDate) -> u32
pub fn best_streak(&self) -> u32
```

Это же и требование Leptos (`docs/COMMON_BUGS.md`): выводить значение, а не писать в сигнал
из эффекта.

**Ловушка в `current_streak`, из-за которой ломаются такие трекеры:** если считать «серия =
дни подряд, включая сегодня», то каждое утро до тренировки на экране будет 0, и приложение
выглядит сломанным. Правило: считаем назад от сегодня, если сегодня отмечено; иначе от
вчера. Если и вчера пусто — 0.

**Все эти функции принимают `today: NaiveDate` аргументом**, а не зовут `Local::now()`
внутри. Поэтому они тестируются обычным `cargo test` на нативном таргете, без браузера и без
wasm-раннера. `Local::now()` вызывается ровно в одном месте — в `main.rs`.

Хранилище: один ключ `posture-challenge` в `localStorage` через `web_sys::window()
.local_storage()` + `serde_json`. `Effect::new` пишет при любом изменении сигнала. Без
`gloo-storage` и без `leptos-use` — это ~15 строк.

## Шаги

### 0. Зафиксировать план и проверить тулчейн

**Первое действие: записать этот план в `architecture.md`** (файл сейчас пустой) — решения,
модель данных и «что сознательно не делаем». Для учебного проекта, куда возвращаешься через
месяц, это самый ценный файл в репозитории, и он должен появиться до кода, а не после.

Rust и cargo на целевой машине есть, ставить их не нужно. Проверить и добить недостающее:

```bash
rustc --version && cargo --version          # ожидаем 1.8x+
rustup target add wasm32-unknown-unknown    # идемпотентно, если уже есть — no-op
trunk --version || cargo install trunk      # trunk в базовую установку не входит
```

Если `rustup` нет (Rust поставлен пакетным менеджером, а не rustup) — таргет добавляется
только через rustup, тогда его придётся поставить. `cargo install trunk` собирается несколько
минут, это нормально.

### 1. Статичный макет — `mockup.html` + `style.css`

Никакого Rust. Обычный HTML, открывается двойным кликом, правка тени видна сразу —
в отличие от Leptos, где каждая правка это пересборка WASM.

Токены:

```css
:root{
  --bg:#e6e9ef; --fg:#3b4252; --accent:#4c7dff;
  --sh-dark:#c4c8d0; --sh-light:#ffffff; --r:20px;
}
.raised { box-shadow: 6px 6px 12px var(--sh-dark), -6px -6px 12px var(--sh-light); }
.pressed{ box-shadow: inset 6px 6px 12px var(--sh-dark), inset -6px -6px 12px var(--sh-light); }
```

Правила, без которых неоморфизм рассыпается:
- фон элемента совпадает с фоном родителя — иначе тени не читаются как рельеф;
- `.raised` = не сделано, `.pressed` = сделано. Состояние читается формой;
- но выполненные дни получают ещё и заливку `--accent`: на солнце и при низкой яркости одни
  тени не различимы. Это и есть «канон нарушаем там, где он мешает»;
- текст `--fg` на `--bg` ≈ 8:1 по контрасту — нормально даже при полупрозрачном виде.

Кольцо прогресса — CSS, без SVG:
`background: conic-gradient(var(--accent) calc(var(--p) * 1%), transparent 0)`,
где `--p` проставляется инлайн-стилем из Leptos (единственный инлайн-стиль в проекте).

Сетка дней: `grid-template-columns: repeat(auto-fill, minmax(24px, 1fr))` — сама
перестраивается под 30 и под 100 дней, календарная арифметика для неё не нужна вообще.

Верстать при ширине 390px. Кнопка «Отметить день» — не меньше 44×44 и в зоне большого пальца.

### 2. Проект Leptos, оживление макета

`index.html`: `<link data-trunk rel="rust" />`, `<link data-trunk rel="css" href="style.css"/>`,
`<link data-trunk rel="copy-dir" href="public" />`.

Импорт — `use leptos::prelude::*` (в 0.8 это prelude; если компилятор возразит, `leptos::*`).

`main.rs`: загрузить `Challenge` из `localStorage` (или дефолт: name «Идеальная осанка»,
start = сегодня, length = 30, done пустой), положить в один сигнал, `Effect::new` на запись,
`mount_to_body`.

`ui.rs`: `Ring`, `DayGrid` (N клеток, тап переключает дату), `CalendarModal` (месяц + `‹ ›`,

Перенос разметки из `mockup.html` в `view!` — `style.css` переезжает как есть, без правок.

### 3. Настройки, финиш, экспорт

Модалка настроек: длина N (кнопки 30/60/100 + числовое поле), дата старта
(`<input type="date">` — нативный пикер, никакой библиотеки), название челленджа,
полный сброс с подтверждением.

Экран финиша при `is_finished()`: «97 из 100, лучшая серия 34» + «Начать заново»
(меняет только `start`, `done` не трогает).

Экспорт/импорт — осознанно самый ленивый вариант, помечаем `// ponytail:`:
- экспорт: `<a download="posture.json" href="data:application/json;charset=utf-8,{urlencoded}">`
  — без `web_sys::Blob` и без `URL::create_object_url`;
- импорт: `<textarea>` + кнопка «Вставить JSON» — без `FileReader` и его async-обвязки.

### 4. PWA

`public/manifest.json`: name, `display: "standalone"`, `background_color`/`theme_color` = `#e6e9ef`,
иконки 192 и 512.

`public/sw.js` — network-first с откатом в кэш. Именно network-first, а не cache-first:
не нужно версионировать кэш и невозможно застрять на старом билде после деплоя.

```js
self.addEventListener('install', e => self.skipWaiting());
self.addEventListener('activate', e => e.waitUntil(self.clients.claim()));
self.addEventListener('fetch', e => e.respondWith(
  fetch(e.request)
    .then(r => { const c = r.clone(); caches.open('v1').then(x => x.put(e.request, c)); return r; })
    .catch(() => caches.match(e.request))
));
```

Регистрация — скриптом в `index.html`. **Путь регистрации должен учитывать `--public-url`**:
на Pages это `/<repo>/sw.js`, а не `/sw.js`, иначе scope не совпадёт и оффлайн не заработает.

### 5. Деплой на GitHub Pages

```bash
git init
trunk build --release --public-url /<repo-name>/
```

`dist/` → ветка `gh-pages` (или Pages из `/docs`). HTTPS от Pages обязателен: без него
не будет ни установки на домашний экран, ни service worker.

Мелочь, которую видно в URL: папка называется `challange-tracker` — опечатка в
`challenge`. Имя репозитория попадёт в публичный адрес, так что стоит назвать репу
`posture-challenge` или `challenge-tracker`.

## Что сознательно не делаем

- **Пушей нет** — вместо них штатный будильник. Web Push потребовал бы сервера с
  VAPID-ключами: больше работы, чем всё приложение целиком.
- **Синка между устройствами нет** — трекер живёт на одном телефоне, страховка это
  экспорт JSON. Добавлять, если реально начнёшь отмечать с двух устройств.
- **Один челлендж за раз, архива попыток нет** — «Начать заново» переиспользует ту же
  запись. Добавлять, когда захочешь сравнивать циклы между собой.
- **Чеклист упражнений и таймер** — модель дня осталась одной галочкой. `BTreeSet<NaiveDate>`
  расширяется до `BTreeMap<NaiveDate, DayLog>` без потери данных, когда понадобится.
- **Тёмной темы нет** — добавляется одним `@media (prefers-color-scheme: dark)` с переопределением
  тех же ~6 переменных, но тени под тёмный фон придётся подбирать заново.
