# Challenge Tracker — трекер челленджа на Leptos CSR + неоморфизм

## Context

Есть идея: отслеживать личный челлендж по осанке. Нет ни дизайна, ни архитектуры.
Дополнительное требование, которое определяет всё остальное: проект должен быть учебным
пет-проектом на **Rust** — в него нужно заходить, читать код, изучать фреймворк и дописывать
своё. Дизайн — неоморфизм.

Отсюда: приложение не «самое простое из возможных», а «самое простое из возможных **на Rust
в браузере**». WASM ради одной галочки в день — это оверхед, и он здесь и есть цель.

Итог: статичная PWA, скомпилированная в WASM, без бэкенда, данные в `localStorage`,
хостинг на GitHub Pages.

## Принятые решения

| Что | Решение |
|---|---|
| Модель дня | одна галочка: выполнено / нет |
| Срок | фиксированные N дней (настраивается: 30 / 60 / 100 / любое) |
| Пропуск | мягко: текущая серия в ноль, челлендж продолжается, финиш по дате |
| Правка прошлого | тап переключает день, но только в диапазоне `[start, min(today, start+N-1)]` |
| После финиша | модалка итога + `Start over` (сдвигает дату старта, историю НЕ трёт) |
| Экраны | один экран + модалки (настройки, календарь). Роутера нет |
| Первый запуск | обязательная модалка онбординга, закрыть нельзя |
| История | сетка челленджа N клеток на главном + календарь по месяцам в модалке |
| Платформа | PWA mobile-first, работает оффлайн |
| Напоминания | нет. Штатный будильник телефона |
| Хранилище | `localStorage` + экспорт/импорт JSON |
| Стек | Leptos 0.8 CSR + Trunk |
| CSS | один `style.css`, палитра в CSS-переменных |
| Тема | одна светлая + контрастный акцент (канон нарушаем там, где он мешает читать) |
| Язык UI | English. Приложение — `Challenge Tracker`, челлендж по умолчанию — `My Challenge` |
| Деплой | GitHub Pages |
| Порядок | сначала статичный HTML/CSS-макет, потом оживление в Leptos |
| Дизайн | композиция, модалки, состояния, строки UI — отдельный `design.md` |

**Допущение, принятое без вопроса:** день сменяется в полночь по локальному времени
устройства. Отметил в 00:10 после ночной тренировки — попало в новый день; лечится тапом
по вчерашней клетке, поэтому отдельной настройки «граница дня» не делаем.

## Модель данных

```rust
// state.rs
#[derive(Serialize, Deserialize, Clone, PartialEq)]
pub struct Challenge {
    pub name: String,            // по умолчанию "My Challenge", вводится пользователем
    pub start: NaiveDate,        // дата старта
    pub length: u32,             // N дней
    pub done: BTreeSet<NaiveDate>, // ТОЛЬКО выполненные дни
}
```

`BTreeSet` вместо `HashMap<NaiveDate, bool>`: отсутствие даты = не выполнено. «Пропуск» не
требует ни отдельного значения, ни миграции — он получается бесплатно. Serde пишет
`NaiveDate` как `"2026-08-10"`, так что JSON остаётся читаемым руками.

**В сигнале лежит `Option<Challenge>`, а не `Challenge`.** `None` — это «челленджа ещё нет», и
именно оно включает обязательный онбординг (`design.md`). Без `Option` состояние «первый
запуск» невыразимо: дефолтный `Challenge` неотличим от настоящего, и показывать онбординг было
бы нечем. Следствие для записи: `Effect::new` пишет в `localStorage` только когда `Some` —
иначе первый же рендер сохранил бы пустышку и онбординг больше никогда не появился.

**Ничего производного не храним.** Серия, счётчик, процент, признак финиша — функции от
`Challenge` + `today`:

```rust
pub fn day_number(&self, today: NaiveDate) -> i64      // (today - start) + 1
pub fn done_count(&self) -> usize                       // только дни внутри [start, start+N)
pub fn percent(&self) -> u32                            // для --p кольца
pub fn is_finished(&self, today: NaiveDate) -> bool     // day_number > length
pub fn current_streak(&self, today: NaiveDate) -> u32   // тем же окном, стоп на start
pub fn best_streak(&self) -> u32                        // тем же окном
pub fn is_editable(&self, d: NaiveDate, today: NaiveDate) -> bool  // start ≤ d ≤ min(today, start+N-1)
pub fn toggle(&mut self, d: NaiveDate, today: NaiveDate)           // единственная запись в done
pub fn sanitize(self, today: NaiveDate) -> Self                    // clamp(1..365), старт ≤ today
pub fn cols(&self) -> u32                               // 7 / 9 / 12 / 22 от N
pub fn grid_tappable(&self) -> bool                     // только на ярусе 7 колонок
```

**Все метрики считаются окном `[start, start+N)`, включая серии.** Иначе после `Start over`
на экране оказался бы `best streak` из прошлого цикла — число, которое по видимой сетке не
воспроизводится. `current_streak` по той же причине не уходит ниже `start`.

`toggle` и `sanitize` — два места, где данные могут испортиться, поэтому проверки живут
внутри них, а не в UI. `toggle` — единственная запись в `done`, значит отметить завтра
невозможно по построению. `sanitize` зовётся при сохранении настроек и **при импорте JSON**:
второе и есть настоящая граница доверия, поле `Custom` только вторая по важности.

Это же и общее правило Leptos: выводить значение, а не писать в сигнал из эффекта.

`is_editable` — не украшение UI, а логика: она одна отвечает на вопрос «этот день вообще можно
переключить». Тап мимо диапазона не должен ни менять `done`, ни подсвечиваться. Держим её
здесь, рядом с остальными чистыми функциями, чтобы проверять `cargo test`, а не глазами.

**Ловушка в `current_streak`, из-за которой ломаются такие трекеры:** если считать «серия =
дни подряд, включая сегодня», то каждое утро до тренировки на экране будет 0, и приложение
выглядит сломанным. Правило: считаем назад от сегодня, если сегодня отмечено; иначе от
вчера. Если и вчера пусто — 0.

**Все эти функции принимают `today: NaiveDate` аргументом**, а не зовут `Local::now()`
внутри. Поэтому они тестируются обычным `cargo test` на нативном таргете, без браузера и без
wasm-раннера. `Local::now()` вызывается ровно в одном месте — в `main.rs`.

Хранилище: один ключ `challenge-tracker` в `localStorage` через `web_sys::window()
.local_storage()` + `serde_json`. `Effect::new` пишет при любом изменении сигнала, кроме `None`.
Без `gloo-storage` и без `leptos-use` — это ~15 строк.

## Шаги

### 0. Зафиксировать план и проверить тулчейн

**План уже зафиксирован до кода, а не после:** решения, модель данных и «что сознательно не
делаем» — здесь, визуальный дизайн — в `design.md`. Для учебного проекта, куда возвращаешься
через месяц, это два самых ценных файла в репозитории.

Rust, cargo и rustup на машине есть, ставить их не нужно. Проверить и добить недостающее:

```bash
rustc --version && cargo --version          # ожидаем 1.8x+
rustup target add wasm32-unknown-unknown    # идемпотентно, если уже есть — no-op

# trunk готовым бинарём: из исходников он тут не собирается, см. «Факты об окружении»
curl -fsSL https://github.com/trunk-rs/trunk/releases/download/v0.21.14/trunk-x86_64-unknown-linux-gnu.tar.gz \
  | tar -xzf- -C ~/.cargo/bin
trunk --version
```

Если `rustup` нет (Rust поставлен пакетным менеджером, а не rustup) — таргет добавляется
только через rustup, тогда его придётся поставить.

### 1. Статичная вёрстка — `style.css` + разметка прямо в `index.html`

Никакого Rust. Обычный HTML, открывается двойным кликом, правка тени видна сразу —
в отличие от Leptos, где каждая правка это пересборка WASM. Отдельный `mockup.html` не нужен:
`index.html` требуется всё равно, а на шаге 2 его содержимое заменяется на `mount_to_body`.
Верстается только главный экран — он несёт весь рельеф; шиты появляются сразу в Leptos,
потому что в статике их нечем переключать.

**Что именно верстать — `design.md`:** композиция экрана, состояния кнопки и клеток, bottom
sheet и его ловушки, календарь, онбординг, строки интерфейса. Ниже — только токены и правила, на
которых всё это держится.

Токены:

```css
:root{
  --bg:#e6e9ef; --fg:#3b4252; --accent:#4c7dff;
  --sh-dark:#c4c8d0; --sh-light:#ffffff; --r:20px;
}
.raised { box-shadow: 6px 6px 12px var(--sh-dark), -6px -6px 12px var(--sh-light); }
```

Правила, без которых неоморфизм рассыпается:
- фон элемента совпадает с фоном родителя — иначе тени не читаются как рельеф;
- **рельеф кодирует нажимаемость, а не состояние.** Вдавленных теней в интерфейсе нет вообще:
  в макете 215 теней и все `outer`. Ярусы `.raised` / `.raised-sm` / `.raised-flat` различают
  «большая поверхность» / «элемент» / «ненажимаемое», и ничего больше;
- состояние «выполнено / выбрано» — светлая заливка `--accent-tint` с галочкой и текстом
  `--accent-ink`. Заливать насыщенным `--accent` **нельзя** — это ломает первое правило, и рельеф
  превращается в свечение. Разбор — `design.md`;
- текст `--fg` на `--bg` ≈ 8:1 по контрасту — нормально даже при полупрозрачном виде.

Кольцо прогресса — CSS, без SVG:
`background: conic-gradient(var(--accent) calc(var(--p) * 1%), transparent 0)`,
где `--p` проставляется инлайн-стилем из Leptos. Инлайн-стилей в проекте ровно два: `--p` для
кольца и `--cols` для сетки дней.

Сетка дней: `grid-template-columns: repeat(var(--cols), minmax(0, 1fr))` + `aspect-ratio: 1` на
клетке. Именно `minmax(0, 1fr)`, а не `1fr`: `1fr` == `minmax(auto, 1fr)` и не сжимается ниже
минимума содержимого дорожки, а `aspect-ratio` переносит минимум высоты в минимум ширины.
Календарная арифметика ей не нужна вообще, но **`auto-fill` с `minmax(24px, 1fr)` не годится**:
он даёт клетку 24px, а по клетке надо попадать пальцем. Число колонок берётся от N
(7 / 9 / 12 / 22), и ниже 40px клетка перестаёт быть кнопкой — правка прошлого уходит в
календарь. Границы ярусов считаются от высоты экрана, а не на глаз: под сетку остаётся ~300px.
Таблица и причины — `design.md`.

Верстать при ширине 390px. Кнопка `Mark day` — не меньше 44×44 и в зоне большого пальца.
Отступы — по сетке 8px; радиус, тени и 44×44 из неё сознательно выпадают, см. `design.md`.

### 2. Проект Leptos, оживление макета

```toml
[dependencies]
leptos = { version = "0.8", features = ["csr"] }
chrono = { version = "0.4", default-features = false, features = ["clock", "wasmbind", "serde"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
web-sys = { version = "0.3", features = ["Window", "Storage"] }
js-sys = "0.3"   # только encode_uri_component для data: URL экспорта
```

`index.html`: `<link data-trunk rel="rust" />`, `<link data-trunk rel="css" href="style.css"/>`,
`<link data-trunk rel="copy-dir" href="public" />`.

Импорт — `use leptos::prelude::*` (в 0.8 это prelude; если компилятор возразит, `leptos::*`).

`main.rs`: загрузить `Option<Challenge>` из `localStorage` (`None` → показать онбординг), положить
в один сигнал, `Effect::new` на запись — только для `Some`, `mount_to_body`.

`ui.rs`: `Ring`, `DayGrid` (N клеток, тап переключает дату, но только если `is_editable`),
`CalendarModal` (месяц + `‹ ›`, дни недели из `NaiveDate::weekday`), `SettingsModal { first_run }`
— он же онбординг при `first_run = true`.

Статичная разметка из `index.html` переезжает в `view!`, `<body>` остаётся пустым, `<link>` на
CSS меняется на `data-trunk rel="css"`. `style.css` переезжает как есть, без правок.

### 3. Настройки, финиш, экспорт

Модалка настроек: длина N (кнопки 30/60/100 + числовое поле), дата старта
(`<input type="date">` — нативный пикер, никакой библиотеки), название челленджа,
полный сброс с подтверждением **внутри той же панели** (кнопка на месте становится
`Sure? Yes No`) — без `window.confirm()` и без модалки над модалкой.

Тот же компонент с `first_run = true` — это онбординг: поля + `Start` + импорт, без экспорта и
без сброса (сбрасывать нечего). Правила и причины — `design.md`.

Экран финиша при `is_finished()`: `24 of 30 · best streak 12` + `Start over` (меняет только
`start`, `done` не трогает). Закрывается как обычная модалка и возвращается при следующем
открытии: флаг «видел» — локальный сигнал, в `Challenge` он не попадает.

Экспорт/импорт — осознанно самый ленивый вариант, помечаем `// ponytail:`:
- экспорт: `<a download="challenge.json" href="data:application/json;charset=utf-8,{urlencoded}">`
  — без `web_sys::Blob` и без `URL::create_object_url`. Кодирование — `js_sys::encode_uri_component`;
- импорт: `<textarea>` + кнопка `Import` — без `FileReader` и его async-обвязки.

**Импорт защищён тем же подтверждением, что и сброс:** он затирает челлендж так же
безвозвратно, поэтому `Import` на своём месте становится `Overwrite? Yes No`. Спрашивает только
про валидный JSON — на мусор сразу отвечает строкой `Invalid JSON`, ничего не тронув. В
онбординге подтверждения нет: перезаписывать нечего.

Тап по затемнению закрывает шит через `ev.stop_propagation()` на самой панели, а не сверкой
`event.target` с элементом затемнения: клик внутри панели просто не доходит до backdrop. Тот же
эффект короче, и ловушка с `<input type="date">` закрыта так же надёжно.

### 4. PWA

`public/manifest.json`: `name: "Challenge Tracker"`, `display: "standalone"`,
`background_color`/`theme_color` = `#e6e9ef`, иконки 192 и 512.

Сами иконки рисуются одним скриптом на Pillow (он на машине есть) — плоская дуга акцентом на
`--bg`, без неоморфных теней: на 192px рельеф превращается в грязь. Скрипт и обоснование — в
`design.md`. PNG обязателен: iOS для «Добавить на домашний экран» SVG не берёт.

`public/sw.js` — network-first с откатом в кэш. Именно network-first, а не cache-first:
не нужно версионировать кэш и невозможно застрять на старом билде после деплоя.

```js
self.addEventListener('install', e => self.skipWaiting());
self.addEventListener('activate', e => e.waitUntil(self.clients.claim()));
self.addEventListener('fetch', e => e.respondWith(
  fetch(e.request)
    .then(r => { const c = r.clone(); caches.open('v1').then(x => x.put(e.request, c)); return r; })
    .catch(() => caches.match(e.request))
));
```

Регистрация — скриптом в `index.html`, **относительным путём** `register('sw.js')`: под
`--public-url /challenge-tracker/` он сам разворачивается в `/challenge-tracker/sw.js`.
Абсолютный `/sw.js` дал бы scope `/`, не совпадающий с приложением, и оффлайн бы не заработал.

По той же причине `public` копируется с `data-target-path="."`: из `dist/public/sw.js` scope
покрывал бы только `/public/`. Файл обязан лежать в корне билда.

### 5. Деплой на GitHub Pages

Схема — **Pages из `/docs` на master**: ноль CI, ноль вторых веток, ноль subtree-пушей,
деплой это обычный коммит. Цена — артефакты сборки в истории.

```bash
trunk build --release --dist docs --public-url /challenge-tracker/
git add docs && git commit -m "деплой"
```

Дальше вручную (`gh` на машине нет): создать публичный репозиторий `challenge-tracker`,
`git remote add origin …`, `git push -u origin master`, и в Settings → Pages выбрать
`Deploy from a branch` → `master` → `/docs`.

HTTPS от Pages обязателен: без него не будет ни установки на домашний экран, ни service worker.

Локальная папка называется `challange-tracker` — опечатка в `challenge`. Имя репозитория
попадёт в публичный адрес, поэтому репа называется **`challenge-tracker`**: и опечатки нет, и
совпадает с нейтральным именем приложения. Значит `--public-url /challenge-tracker/`, и путь
регистрации service worker — `/challenge-tracker/sw.js`.

### 6. Сверить `architecture.md` и `design.md` с реальностью

Оба файла написаны до кода. В конце — один проход по обоим: если по ходу что-то решилось иначе
(версия Leptos, названия функций, строки интерфейса, размеры), поправить. Документ, который
начал врать, хуже отсутствующего — в него перестают верить и перестают читать.

## Проверка

**Логика (без браузера):**
```bash
cargo test
```
`#[cfg(test)] mod tests` в `state.rs` — 12 тестов, все на фикстуре с макета (старт 16 дней
назад, N = 30, выполнено 13, пропущены дни 4, 9, 12, сегодня пусто):

- серия: сегодня пусто → 4 (считается от вчера); сегодня отмечено → 5; вчера тоже пусто → 0;
  день до старта отмечен → в серию не входит;
- `day_number` на дне 1 и N, `is_finished` на дне N и N+1;
- `is_editable` на `start - 1`, `start + N`, `today + 1`, `today`, `start`;
- `toggle` вне окна не пишет в `done` ничего — именно он защищает данные от мусора;
- `sanitize`: `length = 0` → 1, `length = 10_000` → 365, старт из будущего → сегодня;
- пустое имя → `My Challenge`;
- `cols` на 30 / 35 / 36 / 60 / 100 / 120 / 121 / 365;
- `Start over`: `done` цел, но `done_count` и `best_streak` обнулились;
- JSON round-trip и читаемость дат руками.

**Движок Safari — локально, без телефона.** Chrome по неоморфизму и по нативным контролам врёт:
пустая `<button>` в нём шириной 0, а в WebKit — 16px. На машине есть WebKitGTK 2.52 и
`/usr/bin/WebKitWebDriver` — тот же движок, что в Safari, и он водится по W3C WebDriver обычным
`curl`/`urllib`:

```bash
WebKitWebDriver --port=4455 &
# POST /session с webkitgtk:browserOptions.binary = /usr/libexec/webkit2gtk-4.1/MiniBrowser
#                и args = ["--automation"]
```

Окно под Wayland не уменьшается ниже ~447px, поэтому 375px (iPhone 11 Pro) даётся через `iframe`
стенда: layout viewport внутри iframe ровно 375, а метрики нативных контролов от размера окна не
зависят. Проверено при 375px на N = 30 / 60 / 100 / 365:
`documentElement.scrollWidth == clientWidth` — горизонтального переполнения нет ни на одном ярусе,
клетка 42.1 / 31 / 24.9 / 11.8px.

**Высоту шитов проверять там же и обязательно на 812 и 667**, а не на макетных 825: `max-height`
на flex-колонке сплющивает кнопки раньше, чем включает прокрутку, и на 825 это не проявляется.
Замеряются высоты `.btn` (56), `.btn-secondary` (48), `.input` (48), `textarea` (88) и
квадратность `.cal-cell` — сравнением с CSS, а не на глаз. Разбор — `design.md`, третья ловушка
bottom sheet.

**Pixel-perfect проверяется суммой, а не элементами.** Ожидания при ширине **390** (размер макета)
берутся из `challange-design.pen`, а не из CSS, и снимаются `getBoundingClientRect()` внутри
iframe стенда:

| Что | Ожидание |
|---|---|
| `.sheet` в настройках, в покое | **572** высоты (`04 Settings`) |
| `.sheet` в онбординге | **496** высоты (`03 Onboarding`) |
| `.sheet .icon-btn` и его `svg` | `40×40` и `18×18` |
| `.field` / `.field-label` / `.input` | `72` / `16` / `48` |
| четыре элемента `.pills` | одна ширина `83.5`, высота `44` |
| `.btn-secondary` | `x = 16`, `358×48` |
| `.confirm` и правый край чипов | `48` высоты, край на `360` (= 16 + 358 − 14) |
| `.btn` в настройках | **отсутствует**, в онбординге `56` |

Две первые строки — главные: если сумма сошлась, сошлись все высоты и зазоры внутри. Поэлементные
замеры нужны только чтобы понять, **какая** строка разошлась. Ловушка при чтении результатов:
числа макета живут в системе координат шита (плашка начинается с `x = 0`), замеры — в координатах
страницы (`x = 16`). Правый край чипов 360, а не 344 из макета, — это совпадение, а не расхождение.

Остаётся руками — то, что из headless-браузера не проверяется:

9. Тап мимо шита при **открытом** нативном `<input type="date">` → панель не закрылась.
10. Фокус в поле имени на iOS → панель не ушла под клавиатуру (`85dvh`).
11. Долгий тап и двойной тап по клетке → нет выделения текста и нет зума
    (`touch-action: manipulation`).
12. Тап по кнопке при `:active` → `scale(0.95)` ощущается как нажатие, а не как смена состояния.

## Что сознательно не делаем

- **Пушей нет** — вместо них штатный будильник. Web Push потребовал бы сервера с
  VAPID-ключами: больше работы, чем всё приложение целиком.
- **Синка между устройствами нет** — трекер живёт на одном телефоне, страховка это
  экспорт JSON. Добавлять, если реально начнёшь отмечать с двух устройств.
- **Один челлендж за раз, архива попыток нет** — «Начать заново» переиспользует ту же
  запись. Добавлять, когда захочешь сравнивать циклы между собой.
- **Чеклист упражнений и таймер** — модель дня осталась одной галочкой. `BTreeSet<NaiveDate>`
  расширяется до `BTreeMap<NaiveDate, DayLog>` без потери данных, когда понадобится.
- **Тёмной темы нет** — добавляется одним `@media (prefers-color-scheme: dark)` с переопределением
  тех же ~6 переменных, но тени под тёмный фон придётся подбирать заново.
