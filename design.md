# Дизайн — трекер челленджа. Неоморфизм, mobile-first

Спутник `architecture.md`. Там — стек, модель данных и шаги; здесь — **всё, что видно на
экране**. Это источник истины для шага 1 (`style.css` + разметка в `index.html`): если при вёрстке
возникает вопрос «а как это выглядит и что при этом происходит», ответ должен быть здесь, а не
выдумываться на ходу.

Палитра и правила неоморфизма (`--bg`, `--accent`, `.raised`, кольцо на
`conic-gradient`, сетка на `--cols`) остаются в `architecture.md`, шаг 1 — здесь они не
дублируются, только достраиваются.

## Язык и имена

| Что | Значение |
|---|---|
| Язык интерфейса | **English**. Все кнопки, заголовки, модалки — англоязычные |
| Язык этих документов | русский. Доки — рабочие, интерфейс — продуктовый, это разные вещи |
| Имя приложения (`<title>`, `manifest.json`) | `Challenge Tracker` |
| Имя челленджа по умолчанию | `My Challenge` |
| Репозиторий | `challenge-tracker` |

Почему имя нейтральное, а не «Perfect Posture»: модель дня — одна галочка, она ничем не
привязана к осанке. Нейтральное имя даёт переиспользовать приложение под другую привычку без
переписывания строк. Конкретное «Идеальная осанка» пользователь вводит сам в поле имени —
это пользовательские данные, а не строка интерфейса.

## Главный экран

Композиция сверху вниз:

```
  ┌─────────────────────────┐
  │   My Challenge          │  ← заголовок: имя челленджа
  │                         │
  │        ╭───────╮        │
  │       │  12/30  │       │  ← кольцо: выполнено / N, крупно
  │       │streak 5 │       │     под ним мелко — текущая серия
  │        ╰───────╯        │
  │  Day 12 of 30 · best 8  │  ← номер дня + лучшая серия
  │                         │
  │  ▣▣▣□▣▣▣▣□▣▣▣▣▣▣▣▣▣▣▣  │  ← сетка челленджа, N клеток
  │  ▣▣□▣▣▣▣▣▣░░░░░░░░░░░░  │     ░ — будущие, пригашены
  │                         │
  │      [  Mark day  ]     │  ← зона большого пальца, ≥44×44
  │   ⚙                📅   │  ← только иконки, без подписей
  └─────────────────────────┘
```

**Кольцо и подпись под ним показывают разные числа, это не дублирование.** Внутри кольца —
`12/30` (сколько дней выполнено из N) и текущая серия. Под кольцом — `Day 12 of 30`, то есть
какой сегодня день челленджа по календарю, и лучшая серия. Выполнено 12 из 30, а идёт при этом
день 17 — нормальная ситуация, и её видно только если показывать оба числа.

После финиша строка под кольцом — `Finished · best streak 8`: `Day 31 of 30` выглядело бы как
баг.

**Клетки сетки — без цифр.** 100 номеров на ширине 390px нечитаемы; точная дата есть в
календаре, а для ежедневного тапа номер не нужен.

**Навигация — только иконки** (встроенный SVG прямо в разметке). Без icon-шрифтов и без
библиотек: две иконки не стоят зависимости.

Шестерёнка — контур lucide `settings` (зубчатая обводка плюс круг в центре), скопированный в
разметку как есть. Своя версия «кольцо плюс восемь спиц» на 20px читалась солнцем: спицы есть,
зубьев нет. Календарь — lucide `calendar` без точек-дней: на 20px шесть точек внутри 10px
смазываются в пятно.

### Тапабельные дни — единственное правило

День переключается тапом **только если** `start ≤ день ≤ min(today, start + N - 1)`.

Всё остальное — будущее и всё за пределами `[start, start + N)` — не реагирует на тап и
выглядит пригашённым.

Почему это важнее, чем кажется: в `architecture.md` изначально стояло «тап по любому дню
переключает его», а это разрешает отметить завтра (бессмыслица для трекера) и записать в
`done` даты, которые `done_count()` всё равно не считает — то есть мусор в хранилище и в
экспортированном JSON. Правило выше делает и то и другое невозможным по построению, а не
проверкой при чтении.

Правило одно и действует **в обоих местах**: и в сетке на главном, и в календаре.

### Кнопка `Mark day`

| Состояние сегодня | Вид кнопки | Надпись |
|---|---|---|
| Не отмечено | `.raised` | `Mark day` |
| Отмечено | `.raised` + заливка `--accent-tint`, галочка и текст `--accent-ink` | `Marked` |
| `today` вне тапабельного диапазона | `.raised`, пригашена, `disabled` | `Mark day` |

Кнопка — тот же самый toggle, что и клетка: повторный тап снимает отметку. Поэтому она говорит
на том же языке заливки и галочки, что и вся сетка.

Третья строка покрывает сразу два случая: челлендж уже завершён и дата старта выставлена в
будущее. Отдельной логики для них не нужно — оба выпадают из диапазона.

### Состояние против нажатия — не путать

Два похожих эффекта с разным смыслом, и в CSS они должны быть разведены явно:

- заливка `--accent-tint` + галочка `--accent-ink` — **состояние**: день выполнен. Живёт, пока
  не снимут отметку.
- `:active` + `transform: scale(0.95)` — **мгновение**: палец на элементе прямо сейчас.

Вдавленности нет ни в том, ни в другом: см. «Рельеф не кодирует состояние». Переход —
`transition` ~150ms.

## Онбординг (первый запуск)

Пока челленджа нет, приложение показывает модалку и **не даёт её закрыть**: ни `Esc`, ни тап
по затемнению, ни иконки X, ни кнопки «Skip». Единственный выход — `Start`.

Это тот же компонент, что и настройки, с флагом `first_run`:

| Секция | Обычные настройки | `first_run` |
|---|---|---|
| Имя, длина N, дата старта | есть | есть |
| Главная кнопка | **нет**, сохраняет закрытие шита | `Start` |
| Импорт JSON | есть | **есть** |
| Экспорт JSON | есть | скрыт |
| Полный сброс | есть | скрыт |

Скрытые секции скрыты не «для чистоты», а потому что бессмысленны: сбрасывать и
экспортировать нечего.

**Импорт при первом запуске оставлен намеренно.** Это сценарий «поставил приложение на новый
телефон и восстанавливаюсь из бэкапа». Если импорт живёт только в настройках, путь получается
`Start` → `Settings` → вставить JSON, и созданный секунду назад челлендж затирается — то есть
пользователь обязан сначала сделать лишнее действие, чтобы потом его отменить.

Значения полей при первом запуске: имя — пустое, placeholder `Challenge name`; длина `30`;
дата старта — сегодня. Кнопка `Start` активна и с пустым именем — тогда подставляется
`My Challenge`.

**Границы полей.** Длина — от 1 до 365: `0` дал бы деление на ноль в проценте кольца, большое
число повесило бы браузер количеством клеток. Пилюль ровно четыре — `30 / 60 / 100` и `Custom`
для всего остального, включая годовой челлендж. Дата старта — **не позже сегодня**
(`max` на `<input type="date">`): назад сдвигать нужно (челлендж часто уже идёт), вперёд не
нужно, а запрет разом убирает состояние «`Day 0 of 30`» — его просто не существует. Оба
ограничения применяются и к импортированному JSON, иначе граница доверия остаётся открытой.

**Зачем тогда обязательная модалка, если все поля уже валидны?** Она не про валидацию, а про
одноразовую экскурсию: пользователь один раз видит, что N настраивается и что дату старта
можно сдвинуть назад. Второе — реальный случай: челлендж часто начинают за несколько дней до
того, как поставят приложение, и без этого экрана человек просто не узнает, что дату можно
поправить.

**Что видно за модалкой.** Челленджа ещё нет, поэтому фон — главный экран с дефолтами
(кольцо `0/30`, пустая сетка на 30 клеток) под затемнением. Пустое серое полотно за bottom
sheet смотрелось бы как незагрузившееся приложение.

## Модальные окна

Все модалки — **bottom sheet**: панель выезжает снизу, прижата к нижней кромке. На 390px это
и привычнее, и даёт больше места, и попадает в зону большого пальца.

- Появление: `transform: translateY(100%) → 0` для панели + `opacity` для затемнения.
- Панель — тот же `.raised`, что и остальной интерфейс, со скруглением только сверху.
- Закрытие обычных модалок (настройки, календарь): иконка X в панели **и** тап по затемнению.

### Три ловушки, из-за которых bottom sheet ломается

**Тап по затемнению закрывает лишнее.** Нативный `<input type="date">` — потомок панели, и
клик по нему всплывает до затемнения: модалка закроется прямо во время выбора даты. Лечится
`ev.stop_propagation()` на самой панели — тогда клик внутри до затемнения просто не доходит.
Сверять `event.target` с элементом затемнения тоже можно, но это лишняя проверка и приведение
типов там, где хватает одной строки.

**Клавиатура перекрывает поле имени.** Панель с `position: fixed; bottom: 0` на iOS остаётся
под экранной клавиатурой. Лечится `max-height: 85dvh; overflow-y: auto` на панели — именно
`dvh`, а не `vh`: `vh` не учитывает свёрнутую адресную строку и клавиатуру.

**`max-height` на flex-колонке сплющивает кнопки вместо прокрутки.** Лечение предыдущей ловушки
рождает следующую: когда содержимого больше, чем `85dvh`, flexbox сначала сжимает детей с
`flex-shrink: 1`, и только потом отдаёт дело `overflow-y`. У полей и `textarea` есть минимум по
содержимому, поэтому они держатся; у кнопки минимум — одна строка текста, и она садится ровно до
неё. Замерено в движке Safari при 375×812 (настройки с открытым импортом): главная кнопка
рисовалась 28px вместо 56, второстепенные — 21px вместо 44. Лечится `.sheet > * { flex-shrink: 0 }`.

Дефект тем сильнее, чем короче экран, и на макетных 825px его не видно вообще — там содержимое
влезает впритык. **Шиты проверяются на 812 и 667**, иначе поломка уезжает в прод. Правило
осталось в силе и после того, как настройки в покое стали макетными 572px: шит с раскрытым
импортом прокручивается уже на 812, а обычные настройки — на 667.

### Экран финиша

Bottom sheet **поверх** главного экрана, а не вместо него: `Challenge complete`, итог и кнопка
`Start over`. Итог по макету — три элемента по центру с `gap 6`: трофей (lucide `trophy`, 40px,
`--accent`), затем `24 of 30` 32/600 и `best streak 9` 14px `--fg-muted`. Одной строкой 13px
итог челленджа выглядел бы как подпись под кольцом, а это единственный экран, где число — награда.

`Start over` ставит `start = today` и не меняет ни `length`, ни `done`. Числа при этом честно
обнуляются: метрики считаются окном `[start, start + N)`, а прошлый цикл в новое окно не
попадает. Историю видно в календаре — там прошлые галочки остаются с тинтом (см. ниже).

Закрывается как обычная модалка — и **возвращается при следующем открытии приложения**. Флаг
«я это уже видел» живёт в локальном сигнале и не сохраняется: `is_finished` — производное от
`Challenge` + `today`, а производное мы не храним (`architecture.md`, «Модель данных»).

Компромисс осознанный. Незакрываемый финиш был бы хуже: после завершения нельзя было бы ни
посмотреть свою сетку, ни дойти до настроек, чтобы сдвинуть дату старта.

### Полный сброс

Кнопка `Reset everything` — обычного стиля, без отдельного «опасного» цвета: во всём
приложении один акцент, вводить второй ради одной кнопки не стоит. Защита — не цвет, а
подтверждение.

Подтверждение **внутри** панели настроек: кнопка на своём месте превращается в
`Sure?  Yes  No`. Никакого `window.confirm()` (выбивается из неоморфизма) и никакой модалки над
модалкой (два затемнения, два z-index, две анимации ради одного вопроса). Помечаем
`// ponytail:`.

Вид строки подтверждения по макету: одна выпуклая плашка высотой 48, скругление 14, внутри слева
вопрос 15px обычного веса, справа два чипа 32×auto со скруглением 10 и текстом 14/600 — `Yes` с
заливкой `--accent-tint` и текстом `--accent-ink`, `No` без заливки. Не голый ряд кнопок: плашка
показывает, что вопрос заменил собой одну кнопку, а не добавился к ним.

## Календарь — состояния дня

| Состояние | Вид | Тапабельно |
|---|---|---|
| Выполнено | `.raised-sm` + заливка `--accent-tint`, число `--accent-ink` | да |
| Пропущено (прошлое внутри челленджа) | `.raised-sm`, число `--fg` | да |
| Будущее или вне `[start, start + N)` | `.raised-flat`, число `--fg-muted` | нет |
| Сегодня | рамка `--accent` 2px поверх своего состояния | да |

**Когда две строки спорят, заливка выигрывает у диапазона.** День может одновременно лежать в
`done` и вне `[start, start + N)` — ровно это происходит после `Start over`: старт съезжает на
сегодня, и все прошлые галочки выпадают из окна. Такой день остаётся с тинтом и галочкой, но
тапом не переключается: вид отвечает за «это было сделано», `is_editable` — за «это можно
менять». Без этого правила календарь после `Start over` выглядел бы так, будто историю стёрло,
хотя `Start over` её как раз и не трогает.

**Неактивные дни гасятся рельефом, а не прозрачностью — и в календаре, и в сетке.**

В календаре внутри клетки живёт дата, и прозрачность гасит её вместе с рельефом: число уходит к
контрасту ≈ 2.5:1. Дату видно должно быть всегда — она и есть то, зачем календарь открывают.
Поэтому гасится только тень, а число становится `--fg-muted`.

Изначально для сетки на главном было записано другое правило: клетки там без цифр, значит
будущие дни можно притушить целиком через `opacity: 0.45`. **На отрисовке оказалось, что нельзя.**
У клетки видна ровно одна деталь — её тень; прозрачность делает эту тень чуть светлее, и
будущий день становится неотличим от пропущенного. Три состояния схлопываются в два. Поэтому в
сетке тот же `.raised-flat`, что в календаре: заливка + галочка = выполнено, глубокий рельеф =
пропущено, почти погашенный = будущее. Три разных вида, ни один не спорит с другим.

Рамка «сегодня» — не отдельное состояние, а метка сверху: сегодня может быть и выполненным, и
пропущенным.

Почему одних теней недостаточно для «выполнено»: на солнце и при низкой яркости рельеф
неразличим, поэтому выполненные дни получают ещё и заливку. Это тот же самый «нарушаем канон
там, где он мешает читать», что и в `architecture.md`.

## Токены отступов и размеров

**Шаг сетки — 8px, и он относится только к отступам:** `padding`, `margin`, `gap` берутся из
`4 / 8 / 12 / 16 / 24 / 32`.

**Вне этой сетки — намеренно:**

| Токен | Значение | Почему не по 8px |
|---|---|---|
| `--r` (скругление) | `20px` | эстетический выбор для неоморфизма, 16 жёстче, 24 «мыльнее» |
| Тени | `6px 6px 12px` | подобраны под `--bg`; смена на 8/16 требует пересбора всей палитры теней |
| Минимум касания | `44×44` | минимум Apple HIG, это не декоративное число |
| Клетка сетки дней | `44×44` при N = 30 | это минимум касания; при больших N меньше, см. ниже |

Это записано явно, чтобы «всё по 8px» и «`--r:20px`» не читались через месяц как противоречие.

### Рельеф не кодирует состояние

**Правило:** рельеф отвечает на вопрос «это элемент, по которому можно нажать», и ни на какой
другой. Состояние («выполнено», «выбрано») передаётся заливкой `--accent-tint` и галочкой или
текстом `--accent-ink`. Вдавленных теней в интерфейсе нет ни одной.

Это записано так жёстко потому, что первая версия этих доков утверждала обратное — «`.pressed` =
сделано, состояние читается формой» — и по ней был написан код: вдавленный колодец кольца,
вдавленные выполненные дни, вдавленные инпуты и выбранная пилюля. **Макету это противоречило с
самого начала:** в `challange-design.pen` 215 теней и все до единой `outer`, включая выбранный
вариант обработки выполненного дня (`Explored C - chosen treatment`) — тинт плюс галочка при той же
выпуклой тени. На телефоне расхождение сразу стало видно.

**Арбитр — `.pen`, а не проза.** Проза объясняет причины, картинка задаёт вид; когда они
расходятся, правится проза.

### Три размера рельефа, а не один

Выяснилось при отрисовке макета: одна пара теней `6px/12px` не работает на всех размерах —
на клетке 44px такой рельеф съедает саму клетку.

| Класс | Тени | Где |
|---|---|---|
| `.raised` | `6px 6px 12px` | большие поверхности: `Mark day`, `Start`, `Start over`, колодец кольца |
| `.raised-sm` | `4px 4px 8px` | клетки дня и календаря, поля ввода, пилюли длины, круглые иконочные кнопки, строка подтверждения и её чипы, второстепенные кнопки |
| `.raised-flat` | `2px 2px 4px` | неактивные дни в календаре и в сетке — рельеф почти погашен, но клетка ещё читается |

### Иерархия кнопок в шите

| Роль | Вид | Кто |
|---|---|---|
| Главное действие | `.raised`, во всю ширину, 56px, скругление `--r`, 17/600 | `Start`, `Start over` |
| Второстепенное | `.raised-sm`, во всю ширину, **48px**, скругление 14, 15/400 по центру, текст `--fg-muted` | `Export JSON`, `Import JSON` |
| Второстепенное опасное | то же, но текст `--fg` | `Reset everything` |

Ярусы различаются высотой, скруглением, весом и глубиной тени, а не шириной: в макете обе
плашки полноширинные. Опасность у сброса передаётся не цветом, а подтверждением — цвет только
перестаёт быть приглушённым.

**Первая вёрстка сделала второстепенные кнопки пилюлями по содержимому, левым краем, 44px.** Это
было прочтение прозой, а не по макету: в `04 Settings` все три — плашки 358×48 с текстом по
центру. Ширина как признак иерархии в этом дизайне не используется вообще.

**Кнопки `Save` в шите настроек нет, и это не недосмотр макета.** Другого выхода из шита, кроме
`X` и тапа по затемнению, дизайн не предусматривает — «отмены» в нём просто не существует,
поэтому закрытие и есть сохранение. Автосохранение на каждый символ (которого мы избежали)
переписывало бы хранилище на каждую букву и подставляло бы `My Challenge` посреди набора имени;
`sanitize` зовётся один раз, при закрытии.

Ловушка на этом пути: `Import` и `Reset everything` закрывают шит **сырым** `on_close`, а не
сохраняющим. Иначе после импорта поверх свежих данных лягут старые значения полей формы, а
сброшенный челлендж вернётся из небытия — оба пути уже записали состояние сами.

**Импорт раскрывается по тапу.** В макете это одна плашка `Import JSON`, без поля для вставки.
Файлового пикера у нас нет (`textarea` вместо `FileReader` — сознательный обходной путь), но
поле незачем держать на экране в сценарии, который случается раз в жизни телефона: тап по
плашке заменяет её блоком «подпись + `textarea` 88px + `Import`». В покое шит совпадает с
макетом и по составу, и по высоте.

### Сетка при больших N: клетка уменьшается, тап отключается

Макет вскрыл противоречие в исходной спецификации. В `architecture.md` сетка была задана как
`repeat(auto-fill, minmax(24px, 1fr))`, но **клетка 24px не нажимается** — это вдвое меньше
минимума касания, а тап по клетке должен переключать день. При N = 30 клетка 44px влезает
идеально, при N = 60 сетка вырастает до 460px вместо 252, при N = 100 — до 660px и выдавливает
кнопку за экран.

Решение: **число колонок задаётся от N, клетка всегда квадратная, сетка всегда влезает.**

Границы ярусов не выбраны на глаз. На экране 825px под сетку остаётся ~300px (заголовок 28,
кольцо 220, строка под ним, отступы 24 между блоками, футер 120, паддинги 32). Верхнее N
каждого яруса — последнее, при котором `ряды × клетка + зазоры` в эти 300px ещё влезает:

| N | Колонки | Зазор | Клетка | Ряды при максимуме N | Высота | Тап |
|---|---|---|---|---|---|---|
| ≤ 35 | 7 | 8px | 44px | 5 | 254px | **да** |
| 36–63 | 9 | 8px | 33px | 7 | 277px | нет |
| 64–120 | 12 | 4px | 26px | 10 | 298px | нет |
| > 120 | 22 | 4px | 12px | 17 (при 365) | 276px | нет |

```rust
let cols = match challenge.length { 0..=35 => 7, 36..=63 => 9, 64..=120 => 12, _ => 22 };
```

**Первая версия этой таблицы была посчитана неверно, и это видно только на скриншоте.** В ней
стояло `> 63 → 12 колонок` с высотой 262px — но 262px это N = 100 (9 рядов), а не N = 144
(12 рядов, 358px). При N = 365 ярус в 19 колонок давал 20 рядов и 376px, и ряд иконок уезжал
под экран. Верхняя граница яруса считается по **максимальному** N в нём, а не по типичному.

Галочка внутри клетки пропадает начиная с 12 колонок, а не с 9: на клетке 33px она ещё
читается, на 26px уже мешает.

CSS: `grid-template-columns: repeat(var(--cols), 1fr)` плюс `aspect-ratio: 1` на клетке — она
остаётся квадратной при любом числе колонок, без арифметики в Rust.

**Ниже 40px сетка становится обзорной.** Клетки перестают быть кнопками (`pointer-events: none`),
и правка прошлого целиком уходит в календарь — там клетка всегда 44px и всегда нажимается.

Это не потеря: смысл сетки на 100 дней — увидеть картину целиком одним взглядом, а не
попадать пальцем в 22px квадрат. А `is_editable` в `state.rs` от этого не меняется: диапазон
разрешённых дат один и тот же, меняется только то, вешает ли сетка обработчик.

### Нативные контролы iOS сбрасываются явно

`button`, `input` и `textarea` получают `appearance: none` в базе. На iOS у `<button>` стоит
`-webkit-appearance: push-button`, а у полей — свои внутренние отступы, и `padding: 0` их не
снимает: пустая кнопка там шириной 16px против 0 в Chrome. У квадратной клетки этот минимум
превращается в минимальную ширину, потому же дорожки описаны как `minmax(0, 1fr)`, а не `1fr`
(`1fr` == `minmax(auto, 1fr)` и ниже минимума содержимого не сжимается). Стрелки `type=number`
живут в теневом DOM и требуют отдельного
`::-webkit-inner-spin-button { appearance: none }`.

**Честная оговорка:** жалоба «квадратики уезжают за экран вправо» этими правилами не
воспроизводится. В движке Safari при 375px переполнения нет ни с ними, ни без них, на всех четырёх
ярусах — 16px минимум нативной кнопки в минимум grid-дорожки не переносится. Правила оставлены как
страховка и ради вида полей на iOS, а не как найденная причина. Что показывал тот скриншот —
неизвестно; на следующем скриншоте того же челленджа сетка влезает.

### Тень шита — не неоморфная

У панели шита одна мягкая тень вниз (`0 -6px 28px` при 22% чёрного), а не пара
`--sh-dark`/`--sh-light`. Неоморфизм требует, чтобы элемент и фон были одной поверхностью, а шит
висит над затемнением — общей поверхности нет, и пара теней превращается в грязь.

### Насыщенный акцент нельзя заливать — он воюет с рельефом

Первая версия макета заливала выполненные дни и кнопку `Marked` чистым `--accent` `#4c7dff`.
Выглядело плохо, и не из-за яркости, а по структурной причине.

Неоморфизм держится на правиле из `architecture.md`: **фон элемента совпадает с фоном родителя,
иначе тени не читаются как рельеф.** Синяя заливка это правило нарушает — клетка перестаёт быть
той же поверхностью. Внутренние тени на ней читаются не как вдавленность, а как свечение и
ореол, поэтому `Marked` выглядела не нажатой, а наклеенной поверх. Отдельная пара теней
подобранная под синий (`#2d51b8`/`#6b92ff`) проблему не решала: она делала пузырь аккуратнее, но
пузырь.

Вторая причина — площадь. Тринадцать насыщенных квадратов плюс большая плашка плюс дуга — это
около 40% экрана в самом насыщенном цвете палитры. Неоморфизм работает шёпотом.

**Принятое правило:**

| Роль | Как выглядит |
|---|---|
| Выполнено / выбрано | заливка `--accent-tint` + `.raised-sm` + галочка `--accent-ink` |
| Насыщенный `--accent` | только дуга кольца, рамка «сегодня» и глифы. Одна громкая точка на экран |
| Главные кнопки (`Mark day`, `Start`, `Start over`) | `.raised`, без заливки |

Тинт лежит в той же светлотной полосе, что и `--bg` (светлота 0.77 против 0.80), поэтому пара
`--sh-dark`/`--sh-light` на нём продолжает читаться как рельеф — клетка остаётся той же
поверхностью, и состояние видно издалека. Галочка добавляет второй, независимый от теней признак: на солнце
рельеф исчезает, а глиф остаётся.

Главные кнопки не заливаются вообще. Если залить и их, акцент перестанет значить «сделано» и
станет просто «тут можно нажать» — а нажать можно почти везде.

**Отвергнутые варианты** (лежат на канве справа как `Explored A` и `Explored B`):

- **A — просто приглушить синий** до `#5470c6`, заливки оставить. Спокойнее, но конфликт
  заливки с рельефом остаётся: `Marked` по-прежнему не выглядит нажатой.
- **B — акцент только галочкой**, без всякой заливки. Самый каноничный неоморфизм, но узор
  челленджа перестаёт читаться одним взглядом, а тонкая галочка хуже держит солнце, чем
  заливка. Это ровно тот аргумент, из-за которого заливка появилась изначально.

### Порядок в онбординге

Поля → `Import JSON` → `Start`. Главное действие внизу, в зоне большого пальца, как и
`Mark day` на главном экране. Импорт выше — он вторичный и нужен меньшинству.

## Типографика

Системный стек: `-apple-system, "Segoe UI", Roboto, sans-serif`. Без веб-шрифтов вообще.

Причина простая: приложение обязано работать офлайн сразу после установки на домашний экран.
Внешний шрифт — это либо запрос к чужому домену, который в самолёте не выполнится, либо
несколько сотен килобайт в репозитории и в кэше service worker. Оба варианта хуже системного
шрифта, который на телефоне и так выглядит уместно.

Контраст `--fg` на `--bg` ≈ 8:1 — с запасом.

## Иконка приложения

Плоский геометрический знак: незамкнутая дуга цвета `--accent` на фоне `--bg`. Тот же
визуальный мотив, что и кольцо прогресса, — приложение узнаётся по нему.

**Без неоморфных теней.** На 192px рельеф из `6px 6px 12px` превращается в грязь, а на
домашнем экране иконка ещё и уменьшается.

Нужен именно PNG: iOS для «Добавить на домашний экран» берёт `apple-touch-icon` и SVG не
принимает. Генерируется без SVG-конвертеров, Pillow есть на машине:

```python
from PIL import Image, ImageDraw
for size in (192, 512):
    img = Image.new("RGB", (size, size), "#e6e9ef")
    pad, w = size * 0.22, int(size * 0.10)
    ImageDraw.Draw(img).arc(
        [pad, pad, size - pad, size - pad], start=-90, end=200, fill="#4c7dff", width=w
    )
    img.save(f"public/icon-{size}.png")
```

## Чего в дизайне сознательно нет

- **Тёмной темы** — добавляется одним `@media (prefers-color-scheme: dark)` на те же ~6
  переменных, но тени под тёмный фон придётся подбирать заново, а это отдельная работа.
- **Второго акцентного цвета** — один `--accent` на всё, включая деструктивные действия.
  Опасность передаётся подтверждением, а не цветом.
- **Анимаций сверх двух** — `transition` тени и `scale(0.95)` на нажатии, slide-up у модалок.
  Ничего инерционного, никаких пружин, никаких библиотек.
- **Локализации** — интерфейс только английский, механизма переключения языков нет.
- **Иконочного шрифта и SVG-спрайтов** — две иконки живут прямо в разметке.
